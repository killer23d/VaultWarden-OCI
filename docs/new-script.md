## ---

**§1 Purpose and Scope**

migrate-volume.sh is a day-2 administrative utility that moves the VaultWarden-OCI

runtime data directory (PROJECT\_STATE\_DIR) from one block device or directory to

another — including from the boot volume to a dedicated data volume, or from one

dedicated volume to another. It is designed for junior admins: it is safe to interrupt,

resumable, fully logged, and confirms destructive steps before acting.

The script lives at:

utilities/migrate-volume.sh

It is **not** part of the application lifecycle. It must never be called by any systemd

unit, timer, backup.sh, restore.sh, maintenance.sh, or startup.sh. Its only

callers are human operators.

PROJECT\_STATE\_DIR is the runtime data root. It is entirely separate from PROJECT\_ROOT.

Typical values:

| Mode | PROJECT\_STATE\_DIR |
| :---- | :---- |
| Boot-only (default) | /var/lib/vaultwarden |
| Separate-volume | /mnt/vw-data (equals DATA\_VOLUME\_MOUNT) |

**Critical geometry fact confirmed by reading docker-compose.yml.example:**

secrets/, .sops.yaml, and the Age key live under PROJECT\_ROOT, never under

PROJECT\_STATE\_DIR. rsync operates on PROJECT\_STATE\_DIR only. These files are

therefore never encountered by rsync and must NOT appear in the exclude list.

### **docker-compose.yml bind-mount pattern (confirmed, no hardcoded paths)**

Every bind-mount that references runtime state uses variable interpolation:

YAML

\- ${PROJECT\_STATE\_DIR:-/var/lib/vaultwarden}/data:/data  
\- ${PROJECT\_STATE\_DIR:-/var/lib/vaultwarden}/logs:/logs  
\# … (all six services follow this exact pattern)

Docker Compose resolves ${PROJECT\_STATE\_DIR} from .env at docker compose up time.

Updating .env is sufficient — no manual edits to docker-compose.yml are needed on

a stock install. The script's post-migration checklist must include a verification step

for operators who have added custom services with hardcoded paths.

**§4 Subcommand Interface**

### **Usage pattern**

sudo utilities/migrate-volume.sh \<subcommand\> \[OPTIONS\]

### **Subcommands**

| Subcommand | Purpose |
| :---- | :---- |
| run | Execute the full migration pipeline (default subcommand) |
| status | Show current migration state (in-progress, completed, none) |
| resume | Resume a previously interrupted migration from the last completed step |
| abort | Roll back a failed or unwanted in-progress migration |
| verify | Re-run the byte-count and sentinel verification step only (non-destructive) |

### **Flags (all subcommands unless noted)**

| Flag | Default | Applies to | Description |
| :---- | :---- | :---- | :---- |
| \--source \<path\> | $PROJECT\_STATE\_DIR | run | Source directory to migrate from |
| \--target \<path\> | *(required)* | run | Destination directory or mount point |
| \--device \<dev\> | *(auto-detect)* | run | Block device for new volume (e.g. /dev/sdb). If omitted and \--target is already mounted, device is inferred from findmnt. |
| \--skip-stack-stop | false | run | Do not stop the Docker stack before migrating. Requires explicit operator acknowledgment at runtime. |
| \--delete-source | false | run | After successful verification, delete the renamed source. Requires typing the source path to confirm. |
| \--dry-run | false | run, resume, verify | Print every action without executing any of it. rsync runs with \--dry-run. No state file is written. |
| \--force | false | run | Skip the pre-migration backup requirement prompt (does not skip backup; skips the "have you backed up?" confirmation). |
| \--yes | false | run | Non-interactive: answer yes to all confirmation prompts. NOT available for \--delete-source confirmation (always requires typing). |
| \--log-file \<path\> | $PROJECT\_STATE\_DIR/logs/migrate-volume-\<timestamp\>.log | all | Explicit log file path. |
| \--help | — | all | Print usage and exit 0\. |

### **Argument parsing rules**

* First non-option positional argument is the subcommand.  
* If no subcommand is given, default to run and print a warning.  
* Unknown flags → print error and \--help excerpt, exit 1\.  
* \--source and \--target accept both absolute paths and paths beginning with \~ (expand with eval).  
* \--device is mutually exclusive with a \--target that is already a mounted filesystem root.

**§5 Bootstrap Block**

The bootstrap block must appear at the top of the file, immediately after the shebang

and file-header comment, following the identical pattern used by every other root-level

script — except PROJECT\_ROOT is one directory up from SCRIPT\_DIR.

Bash

\#\!/usr/bin/env bash  
\# utilities/migrate-volume.sh — VaultWarden-OCI volume migration utility  
\# Migrates PROJECT\_STATE\_DIR between block devices or directories, including  
\# boot-volume-to-dedicated-volume and volume-to-volume migrations.  
\# Safe to interrupt; resumes from the last completed step.  
\#  
\# USAGE: sudo utilities/migrate-volume.sh \<subcommand\> \[OPTIONS\]  
\# Run with \--help for full usage.

set \-euo pipefail  
trap '\_mv\_on\_err $? $LINENO' ERR

SCRIPT\_DIR="$(cd "$(dirname "${BASH\_SOURCE\[0\]}")" && pwd)"  
PROJECT\_ROOT="$(cd "${SCRIPT\_DIR}/.." && pwd)"   \# ← one level up from utilities/  
cd "${PROJECT\_ROOT}"

\# ── Library bootstrap ────────────────────────────────────────────────────────  
REQUIRED\_LIBS=(lib/common.sh lib/storage.sh lib/docker.sh lib/backup-utils.sh)  
for \_lib in "${REQUIRED\_LIBS\[@\]}"; do  
    \[\[ \-f "${PROJECT\_ROOT}/${\_lib}" \]\] || {  
        echo "ERROR: Required library not found: ${PROJECT\_ROOT}/${\_lib}" \>&2  
        exit 1  
    }  
done  
source "${PROJECT\_ROOT}/lib/common.sh"  
init\_common\_lib "$0"  
source "${PROJECT\_ROOT}/lib/storage.sh"  
source "${PROJECT\_ROOT}/lib/docker.sh"  
source "${PROJECT\_ROOT}/lib/backup-utils.sh"

\# ── Environment ───────────────────────────────────────────────────────────────  
load\_env\_file "${PROJECT\_ROOT}/.env"      \# provided by lib/common.sh  
export DRY\_RUN=false                       \# set immediately; overridden by arg parsing  
                                           \# exported so lib functions honour it

**§7 State File**

### **Purpose**

The state file enables resume after an interrupted migration. It is a simple

key=value text file, mode 0600, owned by root.

### **Path**

$PROJECT\_ROOT/.migrate-volume.state

It lives in PROJECT\_ROOT (the repo directory), not PROJECT\_STATE\_DIR, because

PROJECT\_STATE\_DIR is the thing being migrated and may be temporarily unmounted.

### **Token names (one per pipeline step)**

STEP\_VALIDATE\_DONE  
STEP\_BACKUP\_DONE  
STEP\_STOP\_DONE  
STEP\_FORMAT\_DONE  
STEP\_RSYNC\_DONE  
STEP\_VERIFY\_DONE  
STEP\_SOURCE\_RENAMED\_DONE  
STEP\_SOURCE\_DELETED\_DONE  
STEP\_ENV\_UPDATED\_DONE  
STEP\_DROPIN\_UPDATED\_DONE  
STEP\_START\_DONE  
STEP\_HEALTHCHECK\_DONE  
MIGRATION\_COMPLETE

Additional metadata keys written at migration start:

MV\_SOURCE=\<absolute path\>  
MV\_TARGET=\<absolute path\>  
MV\_DEVICE=\<block device or "none"\>  
MV\_START\_TS=\<unix timestamp\>  
MV\_LOG\_FILE=\<absolute path\>  
MV\_SKIP\_STACK\_STOP=\<true|false\>  
MV\_DELETE\_SOURCE=\<true|false\>

### **State file implementation**

Bash

\_mv\_state\_write() {  
    \# Usage: \_mv\_state\_write KEY \[VALUE\]  
    \# VALUE defaults to "true". Atomic write via temp file.  
    local key="$1" value="${2:-true}"  
    local tmp  
    tmp="$(mktemp "${\_MV\_STATE\_FILE}.XXXXXX")"  
    if \[\[ \-f "${\_MV\_STATE\_FILE}" \]\]; then  
        grep \-v "^${key}\=" "${\_MV\_STATE\_FILE}" \> "${tmp}" 2\>/dev/null || true  
    fi  
    printf '%s=%s\\n' "${key}" "${value}" \>\> "${tmp}"  
    chmod 0600 "${tmp}"  
    mv \-f "${tmp}" "${\_MV\_STATE\_FILE}"  
}

\_mv\_state\_read() {  
    \# Usage: \_mv\_state\_read KEY  
    \# Prints value or empty string if not found.  
    \[\[ \-f "${\_MV\_STATE\_FILE}" \]\] || return 0  
    grep "^${1}\=" "${\_MV\_STATE\_FILE}" 2\>/dev/null | cut \-d= \-f2- | tail \-1  
}

\_mv\_state\_has() {  
    \# Usage: \_mv\_state\_has KEY — returns 0 if key is present and non-empty  
    local val  
    val="$(\_mv\_state\_read "$1")"  
    \[\[ \-n "${val}" \]\]  
}

\_mv\_state\_clear() {  
    rm \-f "${\_MV\_STATE\_FILE}"  
}

### **Resume logic**

On resume, read MV\_SOURCE, MV\_TARGET, MV\_DEVICE from the state file and skip

every step whose STEP\_\*\_DONE token is present. Steps are checked in pipeline order.

On \--dry-run, \_mv\_state\_write is a no-op (print the key/value instead).

### **Implementation**

Bash

\_mv\_log() {  
    \# Passthrough to lib/common.sh log functions AND write to log file.  
    \# Usage: \_mv\_log \<level\> \<message\>  
    \# level: info | warn | error | success  
    local level="$1"; shift  
    local msg="$\*"  
    "log\_${level}" "${msg}"                                    \# stdout via lib/common.sh  
    printf '\[%s\] \[%s\] %s\\n' \\  
        "$(date '+%Y-%m-%d %H:%M:%S')" \\  
        "${level^^}" \\  
        "${msg}" \>\> "${\_MV\_LOG\_FILE:-/tmp/migrate-volume.log}"  
}

All internal functions use \_mv\_log info|warn|error|success — never echo or raw

log\_\* calls — so every line is always captured in the audit log.

**§9 Lock**

Exactly one migration may run at a time. Use a file lock via flock.

Bash

\_mv\_acquire\_lock() {  
    local lock\_fd  
    \# Allocate an unused file descriptor dynamically  
    exec {lock\_fd}\>"${\_MV\_LOCK\_FILE}"  
    flock \-n "${lock\_fd}" || {  
        log\_error "Another migration is already running (lock held: ${\_MV\_LOCK\_FILE})."  
        log\_error "Run: sudo utilities/migrate-volume.sh status"  
        exit 1  
    }  
    \# Export fd number so \_mv\_release\_lock can close it  
    \_MV\_LOCK\_FD="${lock\_fd}"  
}

\_mv\_release\_lock() {  
    \[\[ \-n "${\_MV\_LOCK\_FD:-}" \]\] && {  
        flock \-u "${\_MV\_LOCK\_FD}"  
        exec {\_MV\_LOCK\_FD}\>&-  
    }  
}

\_mv\_acquire\_lock is called immediately after argument parsing, before any

pipeline step. \_mv\_release\_lock is registered in the cleanup trap.

**§9.1 Cleanup Trap and ERR Handler**

Bash

\_MV\_CLEANUP\_REGISTERED=false

\_mv\_cleanup() {  
    \# Called on EXIT. Releases lock. Prints elapsed time.  
    \_mv\_release\_lock  
    \_mv\_log info "Elapsed: $(\_mv\_elapsed)"  
}

\_mv\_on\_err() {  
    local rc="$1" lineno="$2"  
    \_mv\_log error "Unexpected error at line ${lineno} (exit ${rc}). Migration halted."  
    \_mv\_log error "Resume with: sudo utilities/migrate-volume.sh resume"  
    \_mv\_log error "Abort with:  sudo utilities/migrate-volume.sh abort"  
    \# Do NOT call \_mv\_cleanup here — EXIT trap fires after ERR trap.  
}

\# Register once, after log file is opened:  
trap '\_mv\_cleanup' EXIT

The set \-euo pipefail at the top of the file means any untrapped non-zero exit

triggers \_mv\_on\_err → EXIT → \_mv\_cleanup automatically.

\_mv\_confirm() {  
    \# Usage: \_mv\_confirm "Prompt text"  
    \# Returns 0 if confirmed, exits 1 if declined.  
    \# Skipped when \--yes is set.  
    \[\[ "${\_MV\_YES:-false}" \== "true" \]\] && return 0  
    local reply  
    read \-r \-p "${1} \[y/N\] " reply  
    \[\[ "${reply}" \=\~ ^\[Yy\]$ \]\] || { log\_error "Aborted by operator."; exit 1; }  
}

\_mv\_confirm\_by\_typing() {  
    \# Usage: \_mv\_confirm\_by\_typing "Prompt" "expected string"  
    \# Always interactive — \--yes does NOT bypass this.  
    local prompt="$1" expected="$2" reply  
    read \-r \-p "${prompt} Type exactly '${expected}' to confirm: " reply  
    \[\[ "${reply}" \== "${expected}" \]\] || {  
        log\_error "Confirmation did not match. Aborted."  
        exit 1  
    }  
}

expected string. \--skip-stack-stop uses \_mv\_confirm with an explicit SQLite WAL

integrity warning message, even when \--yes is set (it bypasses \--yes by calling

\_mv\_confirm\_by\_typing with the word "LIVE").

**§10 The Migration Pipeline**

The pipeline runs as a sequence of named steps. Each step:

1. Checks if its STEP\_\*\_DONE token is present in the state file — skip if resuming  
2. Logs entry with \_mv\_log info "── Step N: \<name\> ──"  
3. Performs its work  
4. Writes its token via \_mv\_state\_write STEP\_\*\_DONE

In \--dry-run mode every destructive action prints \[DRY RUN\] would: \<action\> and

returns without executing. rsync runs with \--dry-run added to its flags.

### **Step 0 — Pre-flight validation (\_mv\_step\_validate)**

Token: STEP\_VALIDATE\_DONE

Checks performed in order; any failure exits 1:

1. require\_commands rsync flock findmnt lsblk df du awk sed mktemp numfmt  
2. Source path exists and is a directory.  
3. Target path is not the same canonical path as source (readlink \-f both).  
4. Target path is not a subdirectory of source (rsync infinite loop guard).  
5. Source is not being written to by a running rsync (/proc/\*/fd check).  
6. If \--device given: device node exists, is a block device, is not currently mounted elsewhere.  
7. Disk space: target has du \-sb source bytes free plus 10% headroom. Uses \_mv\_check\_disk\_space().  
8. Stale backup: warn (not block) if newest backup is older than 24 hours. Uses \_mv\_check\_stale\_backup().  
9. If \--skip-stack-stop and any VaultWarden container is live: require \_mv\_confirm\_by\_typing  
   with the word "LIVE" and display SQLite WAL integrity warning. NOT bypassed by \--yes.  
10. Confirm .env is readable and PROJECT\_STATE\_DIR key is present.  
11. Confirm docker-compose.yml exists in PROJECT\_ROOT.

After all checks pass, write migration metadata to state file:

MV\_SOURCE, MV\_TARGET, MV\_DEVICE, MV\_START\_TS, MV\_LOG\_FILE,  
MV\_SKIP\_STACK\_STOP, MV\_DELETE\_SOURCE

### **Step 1 — Pre-migration backup prompt (\_mv\_step\_backup\_prompt)**

Token: STEP\_BACKUP\_DONE

Unless \--force is given, display:

⚠  Before migrating, a current backup is strongly recommended.  
   Run: sudo ./backup.sh full  
   Once complete, re-run this migration with \--force to skip this prompt.

Then call \_mv\_confirm "Confirm you have a recent backup and wish to proceed.".

This step does NOT run backup.sh itself — the operator must confirm they have one.

Token is written after confirmation so resume skips the prompt.

### **Step 2 — Stop the stack (\_mv\_step\_stop)**

Token: STEP\_STOP\_DONE

Default behaviour (no \--skip-stack-stop):

Bash

stop\_services   \# from lib/docker.sh

Log container state before and after with docker compose ps \--format json.

If \--skip-stack-stop is true, log a prominent warning and proceed.

The operator already confirmed the live-migration risk in Step 0 validation.

### **Step 3 — Format and mount target volume (\_mv\_step\_format)**

Token: STEP\_FORMAT\_DONE

Only runs when \--device was supplied AND the device is not already formatted and

mounted at \--target. Delegates entirely to setup\_data\_volume() from lib/storage.sh:

Bash

setup\_data\_volume "${\_MV\_DEVICE}" "${\_MV\_TARGET}"

setup\_data\_volume() handles: mkfs.ext4, fstab entry, systemctl daemon-reload,

mount, and sentinel creation (.vw-data-volume).

If \--device was not supplied (directory-to-directory migration), skip this step.

### **Step 4 — rsync data transfer (\_mv\_step\_rsync)**

Token: STEP\_RSYNC\_DONE

rsync flags and rationale:

| Flag | Rationale |
| :---- | :---- |
| \--archive | Canonical preserve-everything shorthand (-rlptgoD) |
| \--hard-links | Docker layer files may share inodes |
| \--acls | Preserve POSIX ACLs |
| \--xattrs | Preserve SELinux labels and Linux capabilities |
| \--sparse | SQLite WAL/journal files are frequently sparse; avoids materialising zero blocks |
| \--one-file-system | Prevents traversal into bind-mounted tmpfs or secondary devices |
| \--delete | Makes rsync idempotent on resume |
| \--delete-excluded | Removes excluded files from target on resume |
| \--human-readable \--progress \--stats | Visible feedback for operator |

Append each entry of \_MV\_RSYNC\_EXCLUDES as \--exclude=\<entry\>.

Add \--dry-run to rsync flags when DRY\_RUN=true.

The source path must have a trailing slash: "${\_MV\_SOURCE%/}/".

This tells rsync to copy the directory's contents, not the directory itself.

#### **Correct rsync exclude list**

Bash

readonly \-a \_MV\_RSYNC\_EXCLUDES=(  
    "lost+found/"       \# ext4 fsck dir — permission errors on some kernels  
    ".vw-data-volume"   \# target sentinel; never overwrite with source's copy  
    "\*.sock"            \# dead sockets on target confuse service startup diagnostics  
    "\*.pid"             \# PID files are always stale after stack stop  
)

**Do NOT include secrets/, .sops.yaml, or age-key paths.** These live under

PROJECT\_ROOT, which is a completely separate tree from PROJECT\_STATE\_DIR. rsync

never encounters them and their presence in the exclude list would mislead readers.

### **Step 5 — Verify transfer (\_mv\_step\_verify)**

Token: STEP\_VERIFY\_DONE

Use du \-sb on source and target. Compute percentage delta. Fail if delta exceeds

\_MV\_VERIFY\_TOLERANCE\_PCT (1%). Log sizes using numfmt \--to=iec-i \--suffix=B.

The 1% tolerance accounts for filesystem metadata differences (ext4 journal, inode

tables) between source and target volumes that make a byte-perfect comparison

unreliable across different filesystem types.

### **Step 6 — Rename source (\_mv\_step\_rename\_source)**

Token: STEP\_SOURCE\_RENAMED\_DONE

Rename source to \<source\>.pre-migration.\<timestamp\>. This preserves original data

as a fallback; the operator removes it manually after satisfaction.

If source is a mount point (mountpoint \-q), skip the rename — renaming a mounted

directory is not meaningful. Log instructions to unmount and detach the old volume.

If \--delete-source is set, an additional sub-step runs after rename:

* Use \_mv\_confirm\_by\_typing with the renamed path as the expected string.  
* rm \-rf the renamed directory.

### **Step 7 — Update .env (\_mv\_step\_update\_env)**

Token: STEP\_ENV\_UPDATED\_DONE

First, create a timestamped .env backup:

Bash

cp "${PROJECT\_ROOT}/.env" "${PROJECT\_ROOT}/.env.pre-migration.${\_MV\_TIMESTAMP}"  
chmod 0600 "${PROJECT\_ROOT}/.env.pre-migration.${\_MV\_TIMESTAMP}"

Then update keys using \_mv\_set\_env\_var() (atomic sed \+ temp file, identical to

\_set\_env\_var() in setup.sh):

| Key | New value | Condition |
| :---- | :---- | :---- |
| PROJECT\_STATE\_DIR | ${\_MV\_TARGET} | Always |
| DATA\_VOLUME\_MOUNT | ${\_MV\_TARGET} | If \--device was supplied |
| DATA\_VOLUME\_DEVICE | ${\_MV\_DEVICE} | If \--device was supplied |
| BACKUP\_DIR | ${\_MV\_TARGET}/backups | Only if BACKUP\_DIR was previously the default ${old\_state\_dir}/backups |

**Because docker-compose.yml uses ${PROJECT\_STATE\_DIR:-/var/lib/vaultwarden} for all bind-mounts, updating .env is sufficient. No manual edits to docker-compose.yml are needed for a stock install.**

### **Step 8 — Update systemd drop-in paths (\_mv\_step\_update\_dropin)**

Token: STEP\_DROPIN\_UPDATED\_DONE

For each unit in \_MV\_DROPIN\_UNITS, locate the installed drop-in at:

/etc/systemd/system/\<unit\>.d/vaultwarden-paths.conf

Replace all occurrences of the old PROJECT\_STATE\_DIR path with the new target path

using sed. Write via temp file. After all units updated, run systemctl daemon-reload.

Warn and continue if a drop-in is not found (operator may not have run

setup.sh \--phase=systemd).

### **Step 8a — Install Docker mount guard (\_mv\_step\_mount\_guard)**

Only when \--device was supplied. Delegates to lib/storage.sh:

Bash

install\_docker\_mount\_guard "${\_MV\_TARGET}" "${\_MV\_DEVICE}"

This writes the After=\<mount.unit\> and RequiresMountsFor=\<mount\> drop-in that

setup.sh \--phase=systemd would have written at install time.

### **Step 9 — Restart the stack (\_mv\_step\_start)**

Token: STEP\_START\_DONE

Bash

start\_services   \# from lib/docker.sh

Log Docker Compose's exit code. If start\_services fails, log the error and continue

to Step 10 — health check will surface the failure explicitly.

### **Step 10 — Health check (\_mv\_step\_healthcheck)**

Token: STEP\_HEALTHCHECK\_DONE and MIGRATION\_COMPLETE

Poll docker compose ps \--format json every 10 seconds for up to 120 seconds.

Migration is healthy when all restart: unless-stopped containers report

State \== running with healthcheck passing.

On success: write MIGRATION\_COMPLETE, call \_mv\_print\_checklist.

On timeout: log error with docker compose ps and docker compose logs \--tail=50

commands; do NOT write MIGRATION\_COMPLETE.

\_mv\_check\_disk\_space() {  
    \# Usage: \_mv\_check\_disk\_space \<source\_path\> \<target\_path\>  
    \# Fails if target does not have (source\_bytes \* 1.10) free.  
    local source\="$1" target="$2"  
    local src\_bytes avail\_bytes required\_bytes

    src\_bytes="$(du \-sb "${source}/" | awk '{print $1}')"  
    avail\_bytes="$(df \-B1 \--output=avail "${target}" | tail \-1 | tr \-d ' ')"  
    required\_bytes=$(( src\_bytes \+ src\_bytes / 10 ))   \# source \+ 10% headroom

    \_mv\_log info "Disk space check:"  
    \_mv\_log info "  Source size  : $(numfmt \--to=iec-i \--suffix=B "${src\_bytes}")"  
    \_mv\_log info "  Required     : $(numfmt \--to=iec-i \--suffix=B "${required\_bytes}") (source \+ 10%)"  
    \_mv\_log info "  Target avail : $(numfmt \--to=iec-i \--suffix=B "${avail\_bytes}")"

    if (( avail\_bytes \< required\_bytes )); then  
        \_mv\_log error "Insufficient space on target."  
        \_mv\_log error "  Need : $(numfmt \--to=iec-i \--suffix=B "${required\_bytes}")"  
        \_mv\_log error "  Have : $(numfmt \--to=iec-i \--suffix=B "${avail\_bytes}")"  
        return 1  
    fi

    \_mv\_log success "Disk space OK."  
}

\_mv\_check\_stale\_backup() {  
    \# Warns (does not block) if the newest backup is older than 24 hours.  
    \# Uses list\_available\_backups() from lib/backup-utils.sh.  
    local newest newest\_ts now\_ts age\_hours

    \# list\_available\_backups prints paths sorted newest-first; take the first line.  
    newest="$(list\_available\_backups 2\>/dev/null | head \-1)"

    if \[\[ \-z "${newest}" \]\]; then  
        \_mv\_log warn "No backups found. Strongly consider running: sudo ./backup.sh full"  
        return 0  
    fi

    \# Extract timestamp from filename or fall back to file mtime.  
    newest\_ts="$(stat \-c '%Y' "${newest}" 2\>/dev/null || echo 0\)"  
    now\_ts="$(date \+%s)"  
    age\_hours=$(( (now\_ts \- newest\_ts) / 3600 ))

    if (( age\_hours \> 24 )); then  
        \_mv\_log warn "Newest backup is ${age\_hours}h old: ${newest}"  
        \_mv\_log warn "Consider running: sudo ./backup.sh full"  
    else  
        \_mv\_log info "Backup age OK: ${age\_hours}h old — ${newest}"  
    fi  
}

\_mv\_print\_status() {  
    if \[\[ \! \-f "${\_MV\_STATE\_FILE}" \]\]; then  
        log\_info "No migration in progress or previously recorded."  
        return 0  
    fi

    local src tgt device start\_ts complete

    src="$(\_mv\_state\_read MV\_SOURCE)"  
    tgt="$(\_mv\_state\_read MV\_TARGET)"  
    device="$(\_mv\_state\_read MV\_DEVICE)"  
    start\_ts="$(\_mv\_state\_read MV\_START\_TS)"  
    complete="$(\_mv\_state\_read MIGRATION\_COMPLETE)"

    echo ""  
    echo "  Migration State"  
    echo "  ───────────────────────────────────────────────"  
    printf '  %-20s %s\\n' "Source:"   "${src:-unknown}"  
    printf '  %-20s %s\\n' "Target:"   "${tgt:-unknown}"  
    printf '  %-20s %s\\n' "Device:"   "${device:-none}"  
    printf '  %-20s %s\\n' "Started:"  \\  
        "$(date \-d "@${start\_ts}" '+%Y-%m-%d %H:%M:%S' 2\>/dev/null || echo "${start\_ts}")"  
    printf '  %-20s %s\\n' "Complete:" "${complete:-no}"  
    echo "  ───────────────────────────────────────────────"  
    echo ""

    \# Step-by-step status table  
    local \-a steps=(  
        "STEP\_VALIDATE\_DONE:Validate pre-flight"  
        "STEP\_BACKUP\_DONE:Backup confirmation"  
        "STEP\_STOP\_DONE:Stop stack"  
        "STEP\_FORMAT\_DONE:Format/mount volume"  
        "STEP\_RSYNC\_DONE:rsync transfer"  
        "STEP\_VERIFY\_DONE:Verify byte count"  
        "STEP\_SOURCE\_RENAMED\_DONE:Rename source"  
        "STEP\_SOURCE\_DELETED\_DONE:Delete source"  
        "STEP\_ENV\_UPDATED\_DONE:Update .env"  
        "STEP\_DROPIN\_UPDATED\_DONE:Update systemd drop-ins"  
        "STEP\_START\_DONE:Start stack"  
        "STEP\_HEALTHCHECK\_DONE:Health check"  
    )

    local step token label status\_str  
    for step in "${steps\[@\]}"; do  
        token="${step%%:\*}"  
        label="${step\#\#\*:}"  
        if \_mv\_state\_has "${token}"; then  
            status\_str="✓ done"  
        else  
            status\_str="  pending"  
        fi  
        printf '  %-14s  %s\\n' "${status\_str}" "${label}"  
    done  
    echo ""

    if \[\[ "${complete}" \== "true" \]\]; then  
        log\_success "Migration completed successfully."  
    else  
        log\_warn "Migration is incomplete. Resume with:"  
        log\_warn "  sudo utilities/migrate-volume.sh resume"  
    fi  
}

**§15 \_mv\_do\_abort (abort subcommand)**

Attempts to reverse completed steps in reverse pipeline order. Not every step is

reversible; the function logs a clear message for each irreversible step and

continues.

Bash

\_mv\_do\_abort() {  
    if \[\[ \! \-f "${\_MV\_STATE\_FILE}" \]\]; then  
        log\_info "No migration state found. Nothing to abort."  
        return 0  
    fi

    local src tgt complete  
    src="$(\_mv\_state\_read MV\_SOURCE)"  
    tgt="$(\_mv\_state\_read MV\_TARGET)"  
    complete="$(\_mv\_state\_read MIGRATION\_COMPLETE)"

    if \[\[ "${complete}" \== "true" \]\]; then  
        log\_warn "Migration is already marked COMPLETE."  
        \_mv\_confirm "Abort a completed migration? This will attempt to restore the old state."  
    fi

    log\_warn "Aborting migration. Attempting rollback in reverse order..."

    \# ── Step 10 reverse: stop stack (started on new volume) ──────────────────  
    if \_mv\_state\_has STEP\_START\_DONE; then  
        log\_info "Rollback: stopping stack..."  
        stop\_services || log\_warn "stop\_services failed — continuing rollback."  
    fi

    \# ── Step 8 reverse: restore .env from backup ──────────────────────────────  
    if \_mv\_state\_has STEP\_ENV\_UPDATED\_DONE; then  
        local env\_backup  
        env\_backup="${PROJECT\_ROOT}/.env.pre-migration.$(\_mv\_state\_read MV\_START\_TS 2\>/dev/null || echo '\*')"  
        \# Find the backup by glob if exact timestamp not available  
        env\_backup="$(ls \-t "${PROJECT\_ROOT}"/.env.pre-migration.\* 2\>/dev/null | head \-1)"  
        if \[\[ \-n "${env\_backup}" && \-f "${env\_backup}" \]\]; then  
            cp "${env\_backup}" "${PROJECT\_ROOT}/.env"  
            chmod 0600 "${PROJECT\_ROOT}/.env"  
            log\_success ".env restored from: ${env\_backup}"  
        else  
            log\_warn ".env backup not found — manual restoration required."  
            log\_warn "Keys changed: PROJECT\_STATE\_DIR, DATA\_VOLUME\_MOUNT, DATA\_VOLUME\_DEVICE, BACKUP\_DIR"  
        fi  
    fi

    \# ── Step 6 reverse: restore renamed source ────────────────────────────────  
    if \_mv\_state\_has STEP\_SOURCE\_RENAMED\_DONE; then  
        local renamed  
        renamed="$(ls \-td "${src}.pre-migration."\* 2\>/dev/null | head \-1)"  
        if \[\[ \-n "${renamed}" && \-d "${renamed}" \]\]; then  
            if \[\[ \! \-e "${src}" \]\]; then  
                mv "${renamed}" "${src}"  
                log\_success "Source restored: ${renamed} → ${src}"  
            else  
                log\_warn "Cannot restore: ${src} already exists."  
                log\_warn "Renamed source is at: ${renamed}"  
            fi  
        else  
            log\_warn "Renamed source not found — data on target is the only copy."  
        fi  
    fi

    \# ── Step 8 reverse: reload systemd after .env is back ────────────────────  
    if \_mv\_state\_has STEP\_DROPIN\_UPDATED\_DONE; then  
        log\_warn "systemd drop-ins were updated. To restore them, re-run:"  
        log\_warn "  sudo ./setup.sh systemd"  
        systemctl daemon-reload || true  
    fi

    \# ── Step 9 reverse: restart stack from restored source ───────────────────  
    log\_info "Rollback: attempting to start stack from restored source..."  
    load\_env\_file "${PROJECT\_ROOT}/.env"  
    start\_services || log\_warn "start\_services failed — check manually: docker compose up \-d"

    \# ── Clear state file ──────────────────────────────────────────────────────  
    \_mv\_state\_clear  
    log\_success "State file cleared."  
    log\_warn "Review the rollback above carefully. Some steps may require manual intervention."  
    log\_warn "Check: docker compose ps"  
}

\_mv\_parse\_args() {  
    \# Defaults  
    \_MV\_SUBCOMMAND="run"  
    \_MV\_SOURCE=""  
    \_MV\_TARGET=""  
    \_MV\_DEVICE=""  
    \_MV\_SKIP\_STACK\_STOP=false  
    \_MV\_DELETE\_SOURCE=false  
    \_MV\_FORCE=false  
    \_MV\_YES=false  
    \_MV\_LOG\_FILE=""

    \# First positional arg is subcommand if it does not start with '--'  
    if \[\[ $\# \-gt 0 && "${1}" \!= \--\* \]\]; then  
        \_MV\_SUBCOMMAND="$1"  
        shift  
    fi

    while \[\[ $\# \-gt 0 \]\]; do  
        case "$1" in  
            \--source)        \_MV\_SOURCE="$(eval echo "$2")";  shift 2 ;;  
            \--target)        \_MV\_TARGET="$(eval echo "$2")";  shift 2 ;;  
            \--device)        \_MV\_DEVICE="$2";                 shift 2 ;;  
            \--log-file)      \_MV\_LOG\_FILE="$2";               shift 2 ;;  
            \--skip-stack-stop) \_MV\_SKIP\_STACK\_STOP=true;      shift   ;;  
            \--delete-source) \_MV\_DELETE\_SOURCE=true;          shift   ;;  
            \--dry-run)       DRY\_RUN=true;                    shift   ;;  
            \--force)         \_MV\_FORCE=true;                  shift   ;;  
            \--yes)           \_MV\_YES=true;                    shift   ;;  
            \--help|-h)       \_mv\_usage; exit 0 ;;  
            \*)  
                log\_error "Unknown option: $1"  
                \_mv\_usage  
                exit 1  
                ;;  
        esac  
    done

    \# Default source to current PROJECT\_STATE\_DIR  
    if \[\[ \-z "${\_MV\_SOURCE}" \]\]; then  
        \_MV\_SOURCE="${PROJECT\_STATE\_DIR:-/var/lib/vaultwarden}"  
    fi

    \# Validate required args per subcommand  
    case "${\_MV\_SUBCOMMAND}" in  
        run)  
            \[\[ \-n "${\_MV\_TARGET}" \]\] || {  
                log\_error "--target is required for the 'run' subcommand."  
                exit 1  
            }  
            ;;  
        resume|status|abort|verify)  
            \# No required args  
            ;;  
        \*)  
            log\_error "Unknown subcommand: ${\_MV\_SUBCOMMAND}"  
            \_mv\_usage  
            exit 1  
            ;;  
    esac

    \# Canonicalise paths  
    \_MV\_SOURCE="$(realpath \-m "${\_MV\_SOURCE}")"  
    \[\[ \-n "${\_MV\_TARGET}" \]\] && \_MV\_TARGET="$(realpath \-m "${\_MV\_TARGET}")"  
}

\_mv\_run\_pipeline() {  
    local resuming=false  
    \[\[ "${1:-}" \== "--resume" \]\] && resuming=true

    if \[\[ "${resuming}" \== "true" \]\]; then  
        \[\[ \-f "${\_MV\_STATE\_FILE}" \]\] || {  
            log\_error "No state file found. Cannot resume. Run: sudo utilities/migrate-volume.sh run ..."  
            exit 1  
        }  
        \# Restore source/target/device from state file  
        \_MV\_SOURCE="$(\_mv\_state\_read MV\_SOURCE)"  
        \_MV\_TARGET="$(\_mv\_state\_read MV\_TARGET)"  
        \_MV\_DEVICE="$(\_mv\_state\_read MV\_DEVICE)"  
        \_MV\_SKIP\_STACK\_STOP="$(\_mv\_state\_read MV\_SKIP\_STACK\_STOP)"  
        \_MV\_DELETE\_SOURCE="$(\_mv\_state\_read MV\_DELETE\_SOURCE)"  
        log\_info "Resuming migration: ${\_MV\_SOURCE} → ${\_MV\_TARGET}"  
    fi

    \# ── Execute pipeline steps in order ──────────────────────────────────────  
    \_mv\_run\_step STEP\_VALIDATE\_DONE        \_mv\_step\_validate  
    \_mv\_run\_step STEP\_BACKUP\_DONE          \_mv\_step\_backup\_prompt  
    \_mv\_run\_step STEP\_STOP\_DONE            \_mv\_step\_stop  
    \_mv\_run\_step STEP\_FORMAT\_DONE          \_mv\_step\_format  
    \_mv\_run\_step STEP\_RSYNC\_DONE           \_mv\_step\_rsync  
    \_mv\_run\_step STEP\_VERIFY\_DONE          \_mv\_step\_verify  
    \_mv\_run\_step STEP\_SOURCE\_RENAMED\_DONE  \_mv\_step\_rename\_source  
    if \[\[ "${\_MV\_DELETE\_SOURCE}" \== "true" \]\]; then  
        \_mv\_run\_step STEP\_SOURCE\_DELETED\_DONE \_mv\_step\_delete\_source  
    fi  
    \_mv\_run\_step STEP\_ENV\_UPDATED\_DONE     \_mv\_step\_update\_env  
    \_mv\_run\_step STEP\_DROPIN\_UPDATED\_DONE  \_mv\_step\_update\_dropin  
    \_mv\_run\_step STEP\_START\_DONE           \_mv\_step\_start  
    \_mv\_run\_step STEP\_HEALTHCHECK\_DONE     \_mv\_step\_healthcheck  
}

\_mv\_run\_step() {  
    \# Usage: \_mv\_run\_step \<TOKEN\> \<function\>  
    local token="$1" fn="$2"  
    if \_mv\_state\_has "${token}"; then  
        \_mv\_log info "Skipping (already done): ${fn\#\_mv\_step\_}"  
        return 0  
    fi  
    \_mv\_log info "── ${fn\#\_mv\_step\_} ──────────────────────────────────────────────"  
    "${fn}"  
    \[\[ "${DRY\_RUN}" \== "true" \]\] || \_mv\_state\_write "${token}"  
}

**§19 Naming and Style Conventions**

The agent must follow these conventions exactly. They are derived by reading the

existing codebase, not invented.

### **File header**

Bash

\#\!/usr/bin/env bash  
\# utilities/migrate-volume.sh — VaultWarden-OCI volume migration utility  
\# \<one-line description\>  
\# \<blank line\>  
\# USAGE: sudo utilities/migrate-volume.sh \<subcommand\> \[OPTIONS\]  
\# Run with \--help for full usage.

### **Section separators**

Use the same separator style as setup.sh and maintenance.sh:

Bash

\# ── Section Name ──────────────────────────────────────────────────────────────

Width: 80 characters total. Em-dash (─) characters for the rule.

### **Function naming**

| Scope | Pattern | Example |
| :---- | :---- | :---- |
| Private to this script | \_mv\_\<verb\>\_\<noun\> | \_mv\_step\_validate, \_mv\_check\_disk\_space |
| Step functions | \_mv\_step\_\<name\> | \_mv\_step\_rsync, \_mv\_step\_healthcheck |
| State helpers | \_mv\_state\_\<verb\> | \_mv\_state\_write, \_mv\_state\_read |

No global functions without the \_mv\_ prefix, except main.

### **Variable naming**

| Scope | Pattern | Example |
| :---- | :---- | :---- |
| Script-global config | \_MV\_\<NAME\> (uppercase) | \_MV\_SOURCE, \_MV\_TARGET |
| Script-global constants | readonly \_MV\_\<NAME\> | \_MV\_LOCK\_FILE |
| Local to function | lowercase | local src\_bytes |
| Exported to lib functions | uppercase, no prefix | DRY\_RUN |

### **\[DRY RUN\] prefix**

Every action that would modify state prints:

\[DRY RUN\] would: \<action description\>

via \_mv\_log info "\[DRY RUN\] would: ...". This is consistent with the

\[DRY RUN\] prefix used in backup.sh and restore.sh.

### **Separator lines between pipeline steps**

Each step function begins with:

Bash

\_mv\_log info "── \<step\_name\> ─────────────────────────────────────────────────────"

This matches the visual rhythm of maintenance.sh's phase separators.

### **set \-euo pipefail**

Must be at the top of the file. No set \+e anywhere — use || true or

explicit if conditionals for commands that are allowed to fail.

### **local keyword**

All variables inside functions must be declared with local. No bare assignments

at function scope.

### **Quoting**

All variable expansions must be double-quoted unless word splitting is explicitly

required. Arrays are always expanded with "${array\[@\]}".

### **readonly**

All constants declared at the top of the file use readonly. Arrays use

readonly \-a.

**§20 Acceptance Criteria**

The agent must verify all of the following before considering the script complete.

### **Functional checks**

1. shellcheck \-S warning utilities/migrate-volume.sh — zero warnings or errors.  
2. bash \-n utilities/migrate-volume.sh — syntax valid.  
3. sudo utilities/migrate-volume.sh \--help — prints usage and exits 0\.  
4. sudo utilities/migrate-volume.sh status with no state file — prints "No migration  
   in progress" and exits 0\.  
5. sudo utilities/migrate-volume.sh run \--target /tmp/test-target \--dry-run — prints  
   all planned actions, writes no state file, makes no changes to .env or filesystem.  
6. sudo utilities/migrate-volume.sh run \--target /tmp/test-target \--dry-run a second  
   time — identical output (idempotent).

### **Integration checks**

7. Sourcing lib/common.sh, lib/storage.sh, lib/docker.sh, lib/backup-utils.sh  
   succeeds without error in the context of the script's bootstrap block.  
8. load\_env\_file is called before any .env key is read.  
9. DRY\_RUN is exported before any lib function is called.  
10. \_mv\_acquire\_lock is called before any pipeline step.  
11. \_mv\_cleanup (EXIT trap) always fires — verify by adding exit 1 after lock  
    acquisition and confirming the lock file is released.

### **Safety checks**

12. Running with \--source and \--target pointing to the same canonical path prints  
    an error and exits 1 without modifying any file.  
13. Running with \--target as a subdirectory of \--source prints an error and exits 1\.  
14. Running without sudo prints "must be run as root" and exits 1\.  
15. State file has mode 0600 after any \_mv\_state\_write call.  
16. .env backup has mode 0600 and exists before any \_mv\_set\_env\_var call in  
    Step 7\.

### **Style checks**

17. All function names are prefixed \_mv\_ (except main).  
18. All script-global variables are prefixed \_MV\_ or are DRY\_RUN.  
19. Every function uses local for all internal variables.  
20. No echo calls for log output — all output goes through \_mv\_log.  
21. Section separators are exactly 80 characters wide using ─ (U+2500).  
22. utilities/README.md exists and documents all four scripts in utilities/.
