# rc.14 VM8 temporary production-acceptance harness

**Isolated VM8 test harness — these files are not part of the production release.**

This directory holds the exact six one-shot scripts prepared for the disposable
`ubuntu@vaultwarden-oci-8` Ubuntu 26.04 ARM64 host. They are uploaded here
**only to avoid manual script uploads**. Once accepted, archive the concise
results in `docs/HOST-ACCEPTANCE.md` and delete this temporary branch.

The tested **application** candidate remains independently pinned to
`92b9300f96125d19105cc1d4865024cb49612b28`
on `feature/cf-free-auto-fail-open`; the harness branch's commit is not
an application release. Existing selected rc.13 remains until the upgrade script explicitly
health-gates the supported updater and verifies its encrypted pre-update recovery.

| Phase | Script | Gate |
| --- | --- | --- |
| 01 | `01-upgrade.sh` | rc.13→rc.14 exact-source update through installed updater; verified .vwrec, source and doctor |
| 02 | `02-controlled-stop-rearm.sh` | Known upstream exit1 normalized only after Route cleanup; one new invocation and Fail Open |
| 03 | `03-preboot-reboot.sh` | Reversible DNS-condition guard, opt-in boot unit and app target enablement, real reboot |
| 04 | `04-postboot-verify.sh` | Kernel boot, original data, rc.14, app, new Worker Route Fail Open, all four timers |
| 05 | `05-scheduled-operations.sh` | Actual four scheduled services including local-only encrypted backup, DNS writer skipped |
| 06 | `06-safe-cleanup.sh` | Disable target/timers/boot rearm before removing test-only DNS condition |

**Post-upgrade reconciliation (for an existing accepted update):**
If `01-upgrade.sh` previously returned `update apply exited 0` but
the historical verifier stopped at `installed rc14 versions semantically
differ`, do **not** rerun the updater. The original verifier compared the
dual-architecture source manifest with the installed ARM64-only frozen
manifest. Use the separate read-only
`01b-reconcile-installed-upgrade.sh` against the **original private
evidence directory**, requiring the exact manifest generated by the
updater, all other source bytes, the dedicated disk, the original apply
receipt, and the full installed doctor. This script does not run an
update, restart, or Cloudflare API mutation; only the final protected
reconciliation receipt is written. The corrected `01-upgrade.sh`
contains the same frozen-manifest comparison for new acceptance runs.

**RC14-D interrupted re-arm:** If the once-only controlled stop
prints PASS but `remediation-start --auto-fail-open` then returns 1,
do **not** replay `02-controlled-stop-rearm.sh` or restart the Worker.
The new read-only `02b-diagnose-rearm-readonly.sh` reads only the
original private stdout/stderr evidence, an explicit systemd status and
two independent Cloudflare Route inventory/GET snapshots. It prints a
sanitized error *category*, never stdout/stderr contents or token
values. This identifies whether the Worker started but provider Route
verification failed, or whether the Worker itself did not start.
No replay or public DNS mutation is allowed before that exact state
has been reconciled.

**RC14-D active Worker reconciliation (separate one-shot):**
After an initial automatic Fail Open command returned 1 for a stale
Cloudflare GET, independent diagnostics showed a new healthy Worker
and one correctly owned Route with Fail Open `true`, twice, but no
local invocation-bound receipt. In that exact state only, use
`02c-reconcile-active-route.sh` instead of replaying the stopped
Phase 02: it checks the original protected stdout/stderr category,
current systemd invocation, 2 provider samples, source confinement
and data, then calls the **installed, idempotent**
`vwctl crowdsec ensure-fail-open` **once**. Require `updated=no`;
unexpected `updated=yes` is HOLD, not a silent PASS. It only accepts
the correct new invocation, exact previous Route ID change, direct
Cloudflare Fail Open, installed doctor and original vault fingerprint.
The script writes `reconciled.json` with the initial error preserved,
**not** Phase 02's original `after.json`. Therefore Phase 03's
automatic reboot remains blocked until the rc.15 bounded GET readback
fix is CI-accepted and exercised on an installed release. No public
DNS publication or Worker restart is part of this reconciliation.

**No automatic retries.** Do not rerun an already-started phase after HOLD.
The only automatic work is within the approved one-shot service and explicitly
bounded read-only provider checks. Keep tokens, private journals and the encrypted
recovery evidence off GitHub and out of chat; report only printed PASS/HOLD
markers and private evidence directory paths.

**Download procedure:** take a GitHub *commit SHA* for this temporary branch
and fetch all six files and `SHA256SUMS.txt` from
`https://raw.githubusercontent.com/killer23d/VaultWarden-OCI/<commit>/tests/host-acceptance/rc14-vm8/<name>`,
verify `sha256sum --check SHA256SUMS.txt` and `bash -n`, then execute the first
phase with `bash 01-upgrade.sh`. Always fetch by immutable SHA, never a moving
branch URL. Run later phases one at a time. Reconnect over approved private
OCI access after the genuine reboot triggered by `03-preboot-reboot.sh`; no public SSH is necessary.

**Important scope limit:** the suite contains a reversible test-only
`ConditionPathExists` override for the public Cloudflare DNS writer. It
prevents a scheduled health job from changing DNS on the disposable VM; do
not remove it while the target or any timer remains active. The cleanup script
checks previous private PASS receipts, disables automation, and only then
removes that override. If a phase HOLDs after a partial mutation, diagnose
and reconcile the exact state before proceeding; the successful cleanup
sequence must never be invoked as a blind recovery operation.

**CI check:** `tests/test_rc14_vm8_script_bundle.py` checks the exact pinned
SHA-256 for every script, parses embedded Python, validates Bash syntax, and
checks phase boundaries. Static CI is not a substitute for live VM8 results.
